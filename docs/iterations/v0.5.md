## 迭代目标

让一位没有参与 SDK 实现的 Java 开发者，仅依据文档和可获取的制品，
将三个已有 Spring AI 方法接入可信执行管线，验证审批和重试行为，
并留下可复查的接入记录。根据实际阻塞点完成至多一个 SDK 能力切片，
形成可分发、可复现的候选版本。

独立消费工程证明依赖和接线可用；独立开发者试用证明接入体验。
两项证据分别记录，自动化测试或代理模拟不能代替真实开发者的试用结果。

## 范围与工作顺序

按一位主要开发者估算为 7—10 个有效工作日；试用者排期和制品仓库权限开通时间单列。
以下工期为规划估计，不是已测结果或日历承诺。

| 顺序 | 工作包与预计投入 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| 1 | 独立消费示例，1—2 天 | `examples/spring-ai-adoption/` 独立 Maven 工程、接线说明和自动化验收 | 不继承 SDK 父 POM、不依赖 Playground、不复制 SDK 源码；只通过 Maven 制品接入三个方法 |
| 2 | 独立开发者试用，约 1 天执行与整理 | `docs/adoption/2026-09-first-integration.md`，记录原始方法签名、耗时和阻塞 | 真实试用者依照文档操作；记录维护者提示，未完成的接入如实保留 |
| 3 | 修复一个最主要阻塞点，2—3 天 | 一项可评审的修复或 API 改进，以及更新后的示例 | 有试用证据与失败测试；改进后相同案例通过，已有安全语义保持 |
| 4 | 候选制品与发布门槛，2—3 天 | 版本说明、制品构建/验证配置、消费验证、支持范围说明 | 在隔离 Maven 本地仓库中安装候选制品并编译示例；发布模块通过必需检查 |
| 5 | 回归与迭代复盘，1 天 | 验收记录、剩余阻塞清单、候选版本结论 | 全量 verify、真实 Redis 验收、独立消费与试用结果分别有证据 |

维护者负责实现、回归和候选制品；独立开发者负责实际采用试验；
仓库所有者负责发布渠道与账号条件。用户于 2026-09-11 明确选择“暂未确定，先完成示例和试用说明”；当前尚未指定试用者。
等待试用反馈时可以推进制品构建和文档准备；没有反馈不能把工作包 2 标为完成，
也不能凭猜测启动工作包 3 的扩展 API。

## 第一个可执行切片

从独立消费示例开始：选择查询、预览、写操作三个方法，使用本地确定性业务替身。
初版按已支持的平铺标量接口建立消费基线；真实试用仍保留试用者原有方法签名，
不能预先把所有 DTO 或代理改写掉，再声称不存在接入障碍。

1. 使用隔离的 Maven 本地仓库安装当前 SDK 制品，再单独构建消费工程，避免已有缓存或 reactor 依赖掩盖缺失项。
2. 先加入能失败的消费验收：只读成功；写操作无审批零副作用；精确审批后执行一次；并发重试返回相同结果。
3. 通过显式依赖和应用控制的身份、审批、幂等接线使其通过，并说明各个应用组件的职责。
4. 同层补齐参数篡改、跨租户、同审批换 key 拒绝与审计不包含原始参数/输出的关键边界。

示例不需要真实 LLM、支付账户或线上数据库。依赖首次获取可联网；测试执行不访问外部业务系统。
示例应验证现有工具经公开 API 注册和执行；不为减少配置而省略 authorizer、reviewer policy 或 trusted context。

## 接入记录与改进选择

试用记录至少包含：SDK 提交/版本、Java/Spring 版本、原始三个方法签名、
首次成功调用用时、全部三个方法完成用时、下载等待、额外配置与代码、
每次维护者提示、稳定 reason code，以及未支持的类型或代理形式。
建议体验目标为首次调用 30 分钟内、三个方法 2 小时内；这是待测目标，
不包含依赖下载时间，也不能用达到时间目标掩盖审批或身份配置缺失。

只选一项有证据的改进：

- 若独立工程主要卡在依赖或示例接线，先修依赖、文档或最小装配，不新增领域 API。
- 若原始方法被嵌套 DTO/集合阻塞，只支持实际出现的一种结构；先明确规范化、不可变快照、指纹编码和拒绝边界，再写失败测试。
- 若实际 Spring 代理或接口注解阻塞，先定义一种代理形式的发现规则和重复/未保护工具的拒绝行为，不引入全量扫描。
- gateway 或 MCP 仅在出现具体消费方及调用契约后另立切片；当前不预定为 v0.5 的必交付项。

无阻塞也属于有效结果：完成文档和制品交付，不为凑版本扩大 SDK。
DTO 与代理同时遇阻时，优先解决使试用者能完成三个方法接入的最小一项，另一项明确留待后续。

## 本轮不扩展的边界

保持 [architecture.md](../architecture.md) 中的安全契约：UNKNOWN 不自动重发，
过期 owner 不移交执行权，恢复查询不获得支付能力，不用 TTL 清理重新创建执行权。
不会仅因退款示例存在就提取通用 operation store、工作流或人工强制成功接口。

真实 JVM 崩溃恢复、生产数据库证明、保留/清理设计、通用对账历史、OPA、Kafka、
多渠道审批和多框架适配继续由明确采用需求驱动。当前 Web Playground 的退款缺口
不阻塞本轮独立 Java 接入，视觉重设计不在范围内。
